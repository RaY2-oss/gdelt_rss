# gdelt_rss — GDELT → FreshRSS (наука и технологии)

Один RSS-фид на страну (Азия + Африка) и статическая витрина
`rss.bhutyan.online` поверх той же базы.
Тематика: наука/технологии + смежное (энергетика, космос, кибер, медтех).
Архитектура пайплайна: гейт «похоже на одобренное → пропуск, непохоже →
отказ, посередине → LLM», принцип «один LLM-вызов на дубликат-группу», цикл
обратной связи через `seen_urls` → `train_prefilter.py`. Замена старого
`google_news_rss.py` (Google News → GDELT GKG). Полностью автономный проект:
свой venv, свой `config.py`/`.env`, свои копии `gkg_filter.py`/`seen_store.py`/
`model_rotation.py`/`prefilter.py` (изначально портированы из соседнего
приватного проекта с той же архитектурой, дальше развиваются независимо).

## Основной прогон (`main.py`, две строки cron)

Сбор и оценка разведены по разным строкам cron, потому что стоят они
по-разному. Сбор дешёвый — `run_collect.sh` каждые 15 минут, ровно в темпе
публикации дампов GKG. Оценка дорогая (LLM + e5 + пересборка фидов и
витрины) — `run_score.sh` раз в час. `run.sh` делает обе стадии подряд и
остался для разового прогона руками; в cron его больше нет.

1. **collect** (`pipeline.collect`) — тянет GKG 15-мин дампы за
   `COLLECT_LOOKBACK_HOURS` (overlap перекрывает разрыв между часовыми
   прогонами), `gkg_filter.select` связывает тему (`SCITECH_THEMES`) со
   страной по offset'ам V2 (`MAX_THEME_LOC_GAP`/`MIN_COUNTRY_SHARE`).
   `seen_store.final_urls` отсекает URL с уже вынесенным вердиктом — не
   качаем повторно. Оставшееся: trafilatura извлекает текст/заголовок/дату,
   короткие (`MIN_TEXT_LENGTH`) и не-новостные (интервью/колонки, regex)
   отсеиваются сразу с вердиктом `short`/`non_event` в `seen_urls` (без LLM),
   заголовок хэшируется для дешёвого кросс-издательского дедупа, текст
   эмбеддится e5. Статья пишется в `articles` с `importance=NULL`.

2. **score** (`pipeline.score`) — по каждой стране отдельно:
   - `_group_for_scoring` схлопывает статьи в сюжеты e5-косинусом
     (`DEDUP_COSINE`, с лексическим «мостиком» на калиброванном пороге ниже
     него — см. `feeds._cluster`/`_distinctive_tokens`): **это и есть аналог
     MMR-дедупа из /opt/digest** — один сюжет, разные издания, один
     представитель на группу.
   - Похоже на прошлые одобренные (по e5, дистиллировано в локальный
     классификатор `prefilter.drop_mask`) → уверенный отказ, `importance=0`
     без обращения к LLM, вердикт `rejected` в `seen_urls`. Непохоже ни на
     что известное или классификатора ещё нет (`prefilter.is_ready()` —
     холодный старт, пока в `seen_urls` меньше `PREFILTER_MIN_LABELS`
     размеченных строк) → сюжет уходит на LLM. **Сейчас классификатора почти
     всегда нет, поэтому фактически всё идёт через LLM — это ожидаемо и
     совпадает с логикой /opt/digest на старте.**
   - Представители батчами (`LLM_BATCH`) уходят в `_call_openrouter_raw`
     (свой AI-стек: OpenRouter → Groq → Google, ключи из своего `.env`),
     модель ставит 0..100 по рубрике из `_score_prompt`. Оценка представителя
     копируется на весь сюжет (`articles.importance`).
   - К оценке прибавляется **поправка на политический вес** (`pipeline._adjust`
     → `entities.py`): чем больше в статье РАЗНЫХ *заметных* субъектов
     (персоны/организации из GKG `V1Persons`/`V1Organizations`, заметный =
     встречается минимум в `ENTITY_MIN_DF` статьях окна этой же страны), тем
     выше важность; статья без единого такого субъекта получает штраф
     `ENTITY_PENALTY`. Это лечит остаточный локальный шум («сельский школьник
     сдал экзамен на максимум баллов»): по теме — да, но фигурантов, о которых
     пишет остальная лента, там нет. Ниже `RELEVANCE_CUTOFF` штраф не опускает,
     чтобы статья не вылетела из широкого фида `_all`; вердикт для `seen_urls`
     ставится по СЫРОЙ оценке LLM, иначе предфильтр учился бы на сигнале,
     которого он не видит. Пока в окне страны ни один субъект не перешагнул
     порог заметности, фактор выключен целиком.
   - Вердикт `accepted`/`rejected` (по границе `RELEVANCE_CUTOFF` из того же
     промпта) вместе с эмбеддингом пишется в `seen_urls` для **каждой**
     статьи сюжета — это обучающая выборка для `train_prefilter.py`. Сбой
     всех провайдеров на батч не портит вердикт: `importance` остаётся
     `NULL`, статья переоценивается на следующем часовом прогоне.

3. **build_all** (`feeds.build_all` → `feeds.build_country`) — на страну: это
   фид «все статьи», без верхнего лимита. Статьи за `WINDOW_HOURS` с
   `importance>RELEVANCE_CUTOFF` (граница accepted/rejected у LLM),
   повторная e5-кластеризация дублей
   (те же дубли внутри окна уже могли попасть по отдельности из разных
   дампов), сортировка по важности, перевод (`translate.translate_missing`,
   пропускает уже готовые `title_en`/`text_en`) → `{country}.xml` в
   `OUTPUT_DIR` (nginx `rss_proxy` отдаёт FreshRSS). Порог `RELEVANCE_CUTOFF`
   **не понижается**, даже если у страны мало статей за окно: единственный
   рычаг для «мало новостей» — качество фильтрации выше по пайплайну (темы
   GKG + LLM-релевантность), а не ослабление порога.

4. **prune** — чистка `articles` старше `KEEP_HOURS` (`ARCHIVE_DAYS` +
   суточный запас) и `seen_urls` (`seen_store.prune`, 30 дней, только строки
   без эмбеддинга — размеченные для тренировки не трогаются).

## Перевод на русский (`translate_ru.py`, `translate_worker.py`)

Маршрут ровно один и в два плеча:

    любой язык --Google--> английский --opus-mt-tc-big-en-zle--> русский

Первое плечо делает `translate.translate_missing` (кэш в
`articles.title_en`/`text_en`), второе — локальная Marian-модель через
CTranslate2 в int8. Запасных путей нет намеренно: прямые пары opus X→ru,
M2M100 и MADLAD при живом Google только портили текст, а вреда от плохого
перевода больше, чем от его отсутствия. Нет английского — статья ждёт
следующего прогона.

Переводится не весь бэклог, а окно витрины: тот же запрос, что у
`site.window_rows` (архив за `ARCHIVE_DAYS` суток выше гейта релевантности),
в порядке важности. Витрина — единственный потребитель русского, а она
показывает две недели: очередь по суточному фиду оставила бы тринадцать дней
из четырнадцати непереведёнными. Воркер стоит отдельной строкой cron каждые
20 минут и намеренно уступает дорогу конвейеру
(`run_translate.sh`: свой cgroup, `nice 19`, idle-IO, 2 потока из 4). Бюджет
по времени жёсткий — не успели, остальное возьмёт следующий запуск: очередь
это просто `title_ru IS NULL`.

`glossary.py` — словарь имён собственных, подключённый с двух сторон:
`keep`-термины прячутся под маркер ДО перевода (иначе из «DeepSeek» выходит
«Дип Сикс»), `ru`-термины чинятся ПОСЛЕ, если латиница просочилась в вывод.
Русский вывод поверх себя никогда не переписывается — иначе едут падежи;
нужную форму ставит `morph.py`. Ресурсы модели и словаря живут вне
репозитория: `/opt/translate/ct2` (`CT2_DIR`), `/opt/translate/models`
(`TRANSLATE_HF_HOME`), `/opt/translate/glossary*.tsv` (`GLOSSARY_DIR`).
Соседний проект `/opt/digest` переиспользует симлинком `glossary.py` (правки
в нём задевают оба), а вот `translate_ru.py` ему больше не нужен: там LLM
пересказывает сразу по-русски.

## Витрина (`site.py`, cron внутри `run_score.sh`)

`rss.bhutyan.online` — статический сайт поверх той же `feeds.db`: главная с
лентой, 10 регионов, страница на страну. Никакого рантайма — после часового
прогона генерируется HTML в `SITE_OUT`, дальше всё делает nginx. Отбор,
дедуп и ранжирование не дублируют логику фида, а переиспользуют её целиком
(`feeds.cluster_rows`, `feeds.rank`, то же окно и тот же порог); разница
одна — сайту нужен ещё и размер кластера, сколько изданий подхватило сюжет.
Падение сборки витрины не роняет актуализацию фидов: страница максимум
останется от прошлого прогона.

## Предфильтр и обучение (`prefilter.py`, `train_prefilter.py`)

`prefilter.py` — классификатор-гейт, параметризован путём к артефакту
(`settings.PREFILTER_PATH`), своя БД. `train_prefilter.py` учится на
`seen_urls.accepted`/`rejected` с эмбеддингом, отказывается тренироваться,
пока данных меньше `PREFILTER_MIN_LABELS` строк или `PREFILTER_MIN_MINORITY`
в меньшем классе, калибрует порог `lo` под `PREFILTER_TARGET_RECALL`,
отказывается сохранять модель, если она режет меньше `PREFILTER_MIN_GAIN`
трафика. Запускать вручную по мере накопления `seen_urls` (cron не настроен
намеренно — не самоцель, а инструмент, включаемый когда выборка достаточна):

```
venv/bin/python train_prefilter.py [--force]
```

## Файлы

- `settings.py` — страны (FIPS 10-4), GKG-темы, все пороги/пути, включая
  `PREFILTER_*`/`RELEVANCE_CUTOFF`/`ARCHIVE_DAYS`.
- `config.py` / `.env` — секреты (`OPENROUTER_API_KEY`/`GROQ_API_KEY`/
  `GOOGLE_API_KEY`) и `PROXIES`, читаются `model_rotation.py`.
- `gkg_filter.py`, `seen_store.py`, `model_rotation.py`, `prefilter.py` —
  собственные копии одноимённых модулей общей пайплайн-архитектуры,
  развиваются независимо от других проектов.
- `db.py` — схема SQLite: `articles`, `story_overview*`, `entity_ru`,
  `pipeline_state`; `seen_urls` создаётся через `seen_store.ensure`.
- `entities.py` — политический вес статьи: субъекты из GKG
  `V1Persons`/`V1Organizations` + их док-частота по своему же корпусу вместо
  внешнего словаря политических имён (общий файл с `/opt/digest`,
  самопроверка — `venv/bin/python entities.py`).
- `pipeline.py` — сбор (`collect`) и оценка важности (`score`), включая
  предфильтр-гейт и запись вердиктов в `seen_urls`.
- `feeds.py` — дедуп-кластеризация (переиспользуется витриной), топ-`TOP_N`,
  MMR, генерация часового `{country}.xml`.
- `importance.py` — структурная важность: LexRank по эмбеддингам тел, охват
  по разным доменам, вес субъектов (самопроверка — `venv/bin/python
  importance.py`).
- `topics.py` — подтемы сюжета (корзины лежат данными в `topics.json`).
  Словарь размечает строгие попадания, на них учится one-vs-rest логистическая
  регрессия по эмбеддингам, и она отвечает там, где слово не нашлось
  (`refine`; самопроверка — `venv/bin/python topics.py`, кандидаты в словарь —
  `--suggest`).
- `embedder.py` — e5 через onnxruntime напрямую, без `sentence-transformers`
  и без torch (почему — см. «Известные проблемы»).
- `translate.py` — первое плечо: перевод заголовка/текста на английский через
  бесплатный Google Translate (`deep-translator`, HTTP без ключа и без
  локальной модели — **не** LibreTranslate). `ru`/`en` не переводятся;
  переводятся только уже отобранные в фид статьи, не весь бэклог.
- `translate_ru.py` — второе плечо: английский → русский локальной
  `opus-mt-tc-big-en-zle` через CTranslate2 int8 (самопроверка —
  `venv/bin/python translate_ru.py`).
- `translate_worker.py` / `run_translate.sh` — фоновый воркер перевода,
  очередь `title_ru IS NULL`, жёсткий бюджет по времени.
- `glossary.py`, `morph.py`, `entity_ru.py` — имена собственные: словарь
  (`keep`/`ru`), русская словоизменительная морфология для подстановки в
  нужном падеже, извлечение субъектов для витрины. `glossary.py`
  переиспользуется `/opt/digest` симлинком.
- `site.py`, `site_templates/`, `site_static/` — генератор статической
  витрины и её шаблоны/ассеты (шрифты в репозитории, чтобы страница не
  ходила в чужой CDN).
- `train_prefilter.py` — обучение локального предфильтра на `seen_urls`.
- `main.py` — стадии `collect` / `score`; без аргумента обе подряд.
- `run_collect.sh` (cron `*/15`) — только сбор.
- `run_score.sh` (cron `17 * * * *`) — оценка, пересборка фидов, витрина,
  actualize.
- `run.sh` — обе стадии подряд, для разового прогона руками; в cron не стоит.
- `test_pipeline.py` — самопроверки чистой логики (без
  сети/LLM/e5 — сетевые/LLM-вызовы мокаются), запускаются как обычные
  скрипты: `venv/bin/python test_pipeline.py`.

## Установка

```
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполнить OPENROUTER_API_KEY / GROQ_API_KEY / GOOGLE_API_KEY
```

`config.py` — секреты и сетевые настройки для `model_rotation.py` (тот же
контракт: `import config` ждёт `PROXIES`/`OPENROUTER_API_KEY`/`GROQ_API_KEY`/
`GOOGLE_API_KEY`). Назван отдельно от `settings.py`, чтобы не путать секреты
стороннего модуля с параметрами пайплайна.

## Запуск

```
venv/bin/python db.py             # init (идемпотентно)
venv/bin/python main.py           # разовый прогон: collect + score
```

cron (отдельной строки для читалки нет — см. ниже):
```
*/15 * * * *  /opt/gdelt_rss/run_collect.sh   >> /opt/gdelt_rss/logs/cron_collect.log 2>&1
17   * * * *  /opt/gdelt_rss/run_score.sh     >> /opt/gdelt_rss/logs/cron_score.log 2>&1
*/20 * * * *  /opt/gdelt_rss/run_translate.sh >> /opt/gdelt_rss/logs/cron_translate.log 2>&1
```
`flock` снят с обоих скриптов (2026-07-27): прогоны сознательно могут
накладываться, ни один дамп GKG не должен пропадать из-за того, что
предыдущий прогон ещё идёт. Дедуп держат `seen_urls` и `INSERT OR IGNORE`,
БД в WAL; `VACUUM` в `main.prune` при параллельном прогоне просто
пропускается (эксклюзивную блокировку ему никто не даст).

### Обновление FreshRSS (actualize)

Пересобранный `{country}.xml` сам по себе в категориях `_all` не появится —
его должна забрать читалка. Раньше это делала отдельная строка cron
`35 * * * * /usr/bin/php /root/freshrss/app/actualize_script.php`, но она **не
работала ни разу**: php на хосте нет, FreshRSS живёт в докере, а внутренний
cron контейнера выключен (`CRON_MIN=`). Фиды обновлялись только тогда, когда
кто-то открывал веб-интерфейс — отсюда и «вчерашние новости в `_all`».

Теперь actualize вызывает сам `run_score.sh` последней строкой, сразу после
сборки фидов:
```
docker exec freshrss php /var/www/FreshRSS/app/actualize_script.php
```
Расписания у читалки больше нет, она обновляется по факту готовности данных.
У `actualize_script.php` собственный мьютекс (`data/actualize.freshrss.lock`,
TTL 900 c), поэтому наложение двух вызовов безопасно: второй сам аккуратно
выйдет. Забирает он только те фиды, у которых истёк TTL (`ttl_default` =
1200 c у пользователя `Yan`, у всех 89 подписок `ttl=0`, т.е. «по
умолчанию») — при часовом вызове это всегда все.

## Известные проблемы

**SIGILL в `libtorch_cpu.so` (исправлено 2026-07-27).** У процессора этого VPS
(`QEMU Virtual CPU version 2.5+`) нет ни AVX, ни AVX2 — только до `sse4_2`. В
колесе `torch==2.13.0+cpu` даже базовое MKL-ядро VML
(`mkl_vml_kernel_sTanh_Z0*`) скомпилировано с VEX-инструкциями (`vstmxcsr`),
так что торч падал по `illegal instruction` при работе с e5-моделью — процесс
убивался целиком, без трейсбека, `feeds.build_all()` не выполнялся, час сбора
пропадал. С 2026-07-26 это происходило на каждом прогоне подряд
(`dmesg -T | grep 'invalid opcode'`). Воспроизвести падение по требованию не
удалось, оно плавающее — поэтому torch убран с горячего пути целиком, а не
обойдён.

Лечение: `embedder.py` зовёт onnxruntime напрямую — тот считает своей
математикой (MLAS), с честной диспетчеризацией под старый CPU. Вектора
совпадают с torch побитово (cosine 1.0 на смешанных en/zh/ru-текстах), так
что ~20 000 уже сохранённых в БД эмбеддингов остаются сравнимыми и
переиндексация не нужна.

Через `sentence-transformers` с `backend="onnx"` это сначала и делалось, но
связка sentence-transformers 5.6 / optimum 2.1 при `local_files_only=True`
резолвила `onnx/model.onnx` в `None` и уходила конвертировать модель сама —
опять через torch, опять SIGILL. Поэтому обёртки в горячем пути больше нет
вообще, только `onnxruntime` + `transformers` (токенизатор). По той же
причине локальный перевод идёт через CTranslate2, а не через torch.

Страховка в `run_score.sh` оставлена: если стадия вышла с ненулевым кодом по
любой причине, фиды пересобираются отдельным процессом из того, что уже есть
в БД (модель для этого не нужна) — часовое обновление `_all` не срывается.

## Тюнинг тем

`SCITECH_THEMES` в `settings.py` валидируется по счётчикам прошедших строк в
логе прогона. Инвалидная тема просто не матчится (не ошибка). Пороги
`MAX_THEME_LOC_GAP` / `MIN_COUNTRY_SHARE` подбираются по перцентилям из лога
(как в digest).

## Подписка FreshRSS: один фид на страну

`{country}.xml` — все статьи, часовой прогон (`run_score.sh`), без
TOP_N/MMR-лимита, порог `importance>RELEVANCE_CUTOFF` (тот же, что и вердикт
accepted у LLM — см. `feeds.build_country`). Нерусские/неанглийские статьи
фида идут через `translate.translate_missing`.
