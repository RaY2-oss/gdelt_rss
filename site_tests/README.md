# Проверки витрины

`site.py --selfcheck` проверяет сборку — то, что происходит до записи файлов.
Здесь то, что происходит после: приборы `site_static/app.js` на настоящей
собранной странице, а не на выдуманной разметке. Половина ошибок в них —
рассинхрон с шаблоном (переименовали класс, а селектор остался), и поймать его
можно только на боевом HTML.

| файл | что проверяет |
|---|---|
| `pager.test.js` | листалка: все сюжеты из `search.json`, выбор размера страницы, номера строк |
| `sugg.test.js` | подсказки поиска берут издание из общего списка источников |
| `tools.test.js` | закладки (переживают переход между страницами), похожие сюжеты, клавиши |

## Как гонять

Зависимость ровно одна и в репозитории её нет — на сервере нет ни node_modules,
ни package.json, и заводить их ради трёх файлов незачем:

```sh
npm i jsdom                       # куда угодно, хоть во временную папку
./venv/bin/python site.py /tmp/site        # собрать витрину
NODE_PATH=$(npm root) node site_tests/tools.test.js /tmp/site
```

Без аргумента тесты ищут собранный сайт в `site_tests/site`.

Тесты подставляют своё `localStorage`, `matchMedia`, `IntersectionObserver`,
`scrollIntoView` и `fetch`: в jsdom их либо нет, либо они пустышки, а `app.js`
дёргает всё это на старте.
